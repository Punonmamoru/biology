# レビュー記録：指標の定義と計算の正しさ

実装の経緯を知らないレビュー担当（サブエージェント）に、`kodo` の指標の定義と計算をレビューしてもらった記録。
レビュー担当は、README と docstring に書いた定義式が実装と一致しているかを確かめた。あわせて、定義が科学的に妥当か、境界条件で正しく動くかも調べた。境界条件として見たのは、欠損・静止・1 個体・frame_step > 1・y 軸下向きの座標・短い区間など。
多くの指摘は、反例を作って実際に実行して確かめている。

* 重要度は 3 段階。
  * **重大**：結果が誤る、または誤解を招く。
  * **中**：特定の条件で誤る。または定義があいまいで、比較を誤らせる。
  * **軽微**：文言や改善の提案。
* 方針は、重大と中をすべて修正し、軽微も手間の小さいものは修正する。
* 修正のたびに、指摘の再現例を回帰テストとして `tests/test_review_fixes.py` に入れた。修正前のコードでは 24 件中 19 件のテストが失敗し、修正後はすべて通る。

## レビューで正しいと確かめられたもの

* **速さ・総移動距離・直進性・平均の速さ**
  * 速さ $v_t$ と $\Delta t$ = frame_step / fps は、frame_step > 1・`downsample`・`select` のどれでも正しく伝わる。
  * 総移動距離は欠損をまたいで直線で結ぶので、直進性は 1 を超えない。
  * 平均の速さは L/T で計算されている。
* **転向角**：符号は、y 下向きの座標で「+x に進んだあと画面上方向へ曲がる」と +90° になる。範囲は (−180°, 180°]。
* **ヒートマップ**：図の向きは正しい。ビンの端で点が落ちる例は、2 万回のランダム試行で 0 件だった。
* **最近接個体距離**：正しく計算されている。
* **MSD**：定義どおりで、D = 傾き/4 に偏りはない（D = 0.05 のブラウン運動 200 本で、平均 0.0499）。
* **読み込み**
  * SLEAP h5 の軸の並べ替えは、(T,2,N,F) → (T,F,N,2) で正しい。point_scores も正しく並べ替えられる。
  * TrackMate の µm は mm に換算される。
* **平滑化**：移動平均・Savitzky–Golay のどちらも、等速直線運動を変えない。

## 指摘と対応

### 重大

| # | 指摘 | 対応 |
|---|---|---|
| 1 | **`remove_outliers` が、速い転回や U ターン中の本物の点を消す**（preprocess.py）。x・y を別々に移動中央値にとると、曲がるときに中央値が軌跡から外れる。U ターンの頂点では「1 フレームの移動距離の約 2 倍」外れる。threshold = 15 px で 1 フレームに 7.5 px 以上動くと転回点が消え、そのあとの補間で直線に置き換わる。そのため転向角・直進性が「曲がりの少ない側」に偏る。例：半径 48 px・30°/フレームの円運動で 200 点中 198 点が消えた。 | **修正。** 許す距離を `max(threshold, k_step × 付近の 1 サンプルの移動距離の中央値)`（`k_step = 3`）にした。中央値は窓の中のステップでとる。これで、速く曲がる本物の点は残し、一瞬の飛びだけを除く。速く動いている最中の小さな飛びが残りうることを docstring に書いた（その場合は `remove_jumps` で除ける）。合成データで体の向きが不自然に 180° 反転していた点も直し、ノイズなしの練習用データでは除去が 0 点になった。テスト：`test_remove_outliers_keeps_fast_turns` ほか |

### 中

| # | 指摘 | 対応 |
|---|---|---|
| 2 | **交替性指数で、小さな角度が 1 つ挟まるだけで曲がりが分断・消失する。** 例：θ = [30, 3, 30, 0, 0, −30, −30]° が「右 1 回」になる。 | **修正。** 5° 未満の角度は区間を区切らないようにした。区間を区切るのは、向きが変わったとき、または直進が `max_straight`（3）回続いたとき。区間内の角度は合計する。上の例は「左・右」の 2 回になる。`summarize` から `turn_min_deg`・`turn_max_straight` を渡せる。 |
| 3 | **`summarize`・`save_all_figures` の `min_step` の既定値が 0。** このままでは転向角がぶれで決まり、交替性 0.9 の個体が交替性指数 0.53（「でたらめ」）と出る。 | **修正。** 既定値を `None` にし、`min_step` がなければ転向角の列や図を出さず、警告を表示する。`plot_turning_hist` では `min_step` を必須にした。 |
| 4 | **ROI の進入回数で、境界のぶれによる「短い退出」が除けない。** 例：中に 50 → 外に 1 → 中に 50 …で、`min_samples` をいくつにしても 3 回と数えられる。 | **修正。** `min_samples` ≥ 2 では次の 2 段階で処理する。①内側の区間に挟まれた短い「外」を「内」とみなす。②そのあとで短い「内」を「外」とみなす。上の例は 1 回になる。滞在時間は生の判定のまま数える。 |
| 5 | **時刻 0 の位置が入力形式で違う。** SLEAP は動画の 0 フレーム目が 0 秒、TrackMate・手動 CSV は最初の記録が 0 秒になる。そのため、同じ動画でも初進入時刻がずれる（7.0 s と 2.0 s）。 | **修正。** 時刻を、すべての形式で `フレーム番号 / fps`（動画の 0 フレーム目 = 0 秒）に統一した。表に `roi_<名前>_first_frame`（初進入フレーム）も出す。 |
| 6 | **手動 CSV の frame_step を「全個体の間隔の最大公約数」で決めるので壊れやすい。** 例1：個体ごとにクリックするフレームがずれていると、1 サンプルおきが欠損になり、速さが 1 つも計算できない。例2：半端なフレームが 1 行まざると step = 1 になり、有効データが 21% になる。 | **修正（警告と対処法）。** 個体ごとに「記録が何サンプルおきか」を調べ、2 以上なら警告する。警告では原因と対処（`interpolate_gaps(max_gap=k−1)` で埋める、または個体ごとにファイルを分ける）を表示する。埋めれば速さは正しく出ることをテストで確認した。 |
| 7 | **MSD 指数 α が、検出のぶれで小さく出る。** ブラウン運動に σ = 0.2 mm のぶれを足すと α = 0.81 になる（「閉じこもり」と誤読しかねない）。また、D の当てはめ範囲（既定は記録の 1/4）は誤差が大きい（標準偏差 48%）。 | **修正。** α は、ぶれの分 $c=\max(0, 2\,\text{MSD}(\Delta t)-\text{MSD}(2\Delta t))$（≈ 4σ²）を引いてから両対数で当てはめる（σ = 0.2 で α ≈ 1.06）。`summarize` の MSD の計算範囲と当てはめ範囲の既定値は、記録時間の 1 割にした。D は α が 0.7〜1.3 のときだけ表に出す（軽微 #17 もこれで解消）。 |
| 8 | **検出のぶれで、総移動距離・平均の速さ・直進性が大きく歪む。** そのことが README に書かれていない。例：静止 + σ = 0.2 mm・30 fps・30 秒で、総移動距離が 318 mm になる。 | **文書を修正。** README の指標の節とノートブックに、「これらの指標は fps と平滑化の強さで変わるので、同じ設定どうしでしか比べない」と明記した。設定は `results/設定.txt` に残る。 |
| 9 | **手動 CSV の列名が `x_mm` でも単位が px になり**、警告に従うと 2 重に換算してしまう。 | **修正。** 列名（`x_mm`, `x [mm]`, `x(px)` など）から単位を判定する。`units` の指定と列名が食い違えばエラーにする。 |
| 10 | **y 上向きのデータを読む手段がなく、転向角の左右が黙って逆になる。** ImageJ の "Invert Y coordinates" で書き出した場合など（実データでの発生状況は未確認）。 | **修正。** すべての読み込み関数に `y_down` 引数を追加し、ノートブックに `Y_DOWN` の設定を足した。README に、y 上向きのデータ・下から撮影した映像では左右が反転することを書いた。 |
| 11 | **「フレーム」と「サンプル」が混同されている。** frame_step = 10 なら、`max_gap=8` は 80 フレームの欠損まで埋める。`window` の説明も「前後 window」になっていて誤り。 | **文書を修正。** README・ノートブック・docstring で、引数の単位を「サンプル」に統一した。窓の説明は「前後 window // 2 サンプル」に直した。 |

### 軽微

| # | 指摘 | 対応 |
|---|---|---|
| 12 | ちょうど 180° の U ターンが必ず「左」と数えられる（往復運動で、左に曲がった割合 = 1.0 になる）。 | **修正。** \|θ\| = 180° は左右どちらにも数えない。 |
